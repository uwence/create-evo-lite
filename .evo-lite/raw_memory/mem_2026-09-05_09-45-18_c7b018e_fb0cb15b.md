## 实现细节 (Implementation)
[manual-attestation-staleness]
manual attestation 不再 STALE-exempt + batch attest。PR #72 合入 main@c7b018e(两父 merge),
CI release-gate 6/6 绿 @ 7055f789。

起因是子巢 hungersnakegame8 的使用反馈,加上对它的现场取证:manual 判据在 attest 之后,
它守护的 renderer.ts 增加了 98 行,而 verify-contract status 仍报 PASS。机制在
derive-verdicts.js 的 manual 提前 return(位于 dependsMatches 之前)与 compute-status.js
的 STALE-exempt 分支。这不是展示误差:readinessOf() 把每个非 PASS verdict 映成 closure
blocker,R011 复用同一函数 —— 所以过期的 manual PASS 会让 spec 以 READY 闭环。

设计方向是反的:能自动重跑的(command)盯得紧,只有人能复查的(manual)永久豁免 ——
而视觉/交互/观感恰恰是代码改动最容易破坏、机器最无法复验的那类。

三处改动:derive-verdicts 让 manual 落到 dependsMatches;compute-status 为 manual 也算
git diff(unreachable commit 同样 STALE);close-preview 的 STALE remedy 按 verifierType
分流(manual 应重认证而非重跑一个它没有的 verifier)。remedy 路由本就修了一半:remedyFor
早已算出 machine 标志并用在 UNVERIFIED 上,只有 STALE 分支忽略它。

这是**行为变更不是补漏**:原有三处测试明确断言 manual PASS is STALE-exempt,豁免是有测试
背书的刻意设计。三处均已翻向新合同。突变负控:把提前 return 塞回去,红点精确落在
「manual PASS, deps in changedFiles → STALE (manual is NOT exempt)」。

第二个 commit 是 batch attest:attest 干净树前置 + 它自己写 evidence 弄脏树 → 每条认证一个
commit(子巢 7 条 manual = 7 个 commit)。改为 <criterionId...> 变参,写前全量预校验,
clean-tree 与 rev-parse HEAD 各跑一次,批内共享同一 commitSha/ranAt。未造 rollback。

第三个 commit 只收紧措辞不改实现:原写「all-or-nothing / atomicity」超出实际保证。真正保证的
是 preflight/refusal atomicity(被拒批次不留合法前缀);**不保证**事务性存储 —— 进入写入阶段后
I/O 失败可能留下前缀,不主张回滚语义。这与本分支要修的是同一个病:标签断言超出证据范围。

证据分层(复审校正,采纳):机制与选择性转换 = 独立验证(正负测试 + 端到端进 readiness gate);
子巢「恰好 2 STALE + 5 PASS」= 本机活体证据,无远端 repo 可复算,产品逻辑由测试承担,
活体只是额外 oracle。

边界:12 个文件,只有 verification + 镜像测试。E1(progress.js 的 verified 空证据分支)按裁定
不搭车 —— 它今天爆炸半径为零,那是**独立成 patch 的理由,不是夹带的理由**。E3/E4/AC≤8/
codex 绑定 OUT OF SCOPE。两份评估文档保持未跟踪未提交。
