## 实现细节 (Implementation)
[readme-support-scope-and-engine]
README 支持范围与引擎描述纠正。分支 docs/readme-support-scope-and-engine 以两父 merge 合入 main@1b40814（内容 commit 5f9ad4a + 复审修正 b64d25e）。仅 README.md / README_EN.md，无产品代码，无 package.json。

两处事实性错误：

1. A0 冻结的 S_PRODUCT（win32/linux · x64 · Node 20/22/24，darwin 与 arm64 明确不支持）此前只活在裁决记录里，读者永远看不到。新增「支持的环境」段落置于 Quick Start 之前，并写明包元数据不带 os/cpu 字段，因此 npm install 在不受支持平台上可能成功 —— 声明与安装时强制是两件事，A0 分别裁决过。同时拒绝「requires Node >= 20」这个便利简写：那是当前强制下限而非支持范围，Node 21/23/25 能过运行时门却在范围外。

2. header badge 仍写「Memory — SQLite FTS5」，而 DEFAULT_ENGINE_CHOICE 早已翻到 zvec，#66 之后新子巢默认装 zvec 0.7.0。三处（badge、Local Memory 段、目录树注释）统一改为 Zvec 默认 / SQLite 回退，并写出触发回退的条件。

两轮复审各收紧一条主张边界：
- engines.node >= 20 是兼容性元数据，不是「运行时强制下限」；真正的下限是 index.js 的 assertNodeVersion()。刚把声明/元数据/运行时强制分开一段，不能下一段又并回去。
- 「功能不受影响」承诺过头。代码保证的是可用性（Zvec 不可用则回退 SQLite），不是等价性；翻默认那次的证据记录 Zvec 平均精度 72% vs SQLite 63%，且 SQLite trigram 整类召回缺失。丢召回的回退仍是可用的回退，但描述成无损就是这份文件本来要治的病。

明确不做：package.json 的 os/cpu 字段 —— 那是从声明走向安装时强制，会改变 macOS/arm64 用户能否安装，属于独立议题。同样不做：variadic attest 签名、gitignore 规则下发、drift --verbose 的文档补全 —— 那些是描述不足而非描述错误。
