# Evo-Lite 3.x Product Reset

## Goal

把 create-evo-lite 从 **AI Governance Runtime** 重定义为 **AI Project Continuity Toolkit**。

一句话验收：任何 AI agent 在 1 分钟内、只读 `PROJECT.md` + `docs/specs/` + `docs/devlog.md`，就能正确说出——这个项目是什么 / 现在在哪 / 为什么这么做 / 下一步干什么。

2.x 回答「怎么让 AI 被治理」，3.x 回答「项目大了以后，我和下一个 AI 都不迷路」。不是同一个问题，因此不是同一代产品定义。

## Non-goals

- 不迁移 2.x 治理装置：R001–R014、disposition ledger、verification contract / attestation、architecture IR / drift、spec-portfolio、code-perception、wiki projection、hive、PR-state sync。
- 不在 main 保留 `legacy/`。旧系统留在 git history 与 `maintenance/2.x`，不留在新主线目录树——否则 AI 仍会搜到它、引用它、决定复用它。
- 首版不做 semantic memory、MCP server、git hook、dashboard engine。先证明 Markdown-only 已经够用。
- 不继承 2.x 的三条 blocked backlog（见 §5）。
- 不做 spec 生命周期状态机。spec 只有文件和勾选框。

## Design

### 1. 三个核心对象

- `PROJECT.md` —— 我在哪 / 下一步。人和 AI 共用的驾驶舱。
- `docs/specs/` —— 要做什么 / 怎么验收。开发前规划。
- `docs/devlog.md` —— 做过什么 / 为什么。开发过程记录，3.x 真正的 memory。

任何能力进 core 前必须回答：它是否直接改善这三个问题之一？不能，就不进 core。

### 2. PROJECT.md 硬上限

```text
Identity      <= 10 lines      Specs         <= 20 active rows
Now           <=  5 lines      Known Issues  <= 20 items
Milestones    <= 20 rows       Commands      <= 30 lines
Decisions     <= 20 active rows  Handoff     <= 10 lines
```

溢出不是警告，是驱逐信号：`PROJECT.md` --eviction--> `docs/devlog.md` --aging--> git history。git 是唯一无限容量的 archive，PROJECT.md 不承担历史数据库职责。2.x 的 FOCUS 膨胀成 1835 字符单段，根因就是只有 append 没有 evict。

### 3. Spec 模板与 120 行上限

固定五段：`## Goal` / `## Non-goals` / `## Design` / `## Acceptance Criteria` / `## Open Questions`。超过 120 行不是告警，是「这个 spec 需要拆」的判据。验收标准写成可勾选的事实，例如 `- [ ] fresh install works`。

### 4. 检索是 capability，不是 dependency

```text
canonical truth: Markdown / plain files
  |- rg / grep                      必须永远能工作，零依赖
     |- optional search adapter     SQLite FTS / zvec / future semantic index
```

索引损坏、原生模块编译失败、引擎缺席时，项目仍然 100% 可接手——这才是 lite 的定义。2.x 的反例：`better-sqlite3` 缺席即整条接管链失败。

### 5. Unknown 触发 scope reduction，不触发 project blocking

四个状态必须互不等价：`Known`（有证据）/ `Assumed`（无证据，显式记录假设并缩小范围后继续）/ `Unknown`（未知，不阻塞）/ `Blocked`（仅限不可逆操作、安全、数据破坏、兼容性）。

范例，取代 2.x 的 `[attp-lw-memory-identity]`：

```text
ASSUMPTION  Claude linked-worktree memory identity is not stable.
ACTION      v3 does not support linked-worktree automatic memory lookup.
STATUS      Not blocked.
```

2.x 的三条 blocked backlog 一条都不迁入 3.x，全部降级为历史经验写进 `docs/lessons-v2.md`：(1) 外部宿主身份不可证明时，不构建自动推断链；(2) Runtime health 只检查本产品拥有的事实；(3) Hook 是 convenience，不是 correctness root。

### 6. CLI：四个命令，800 行是上限不是目标

```text
init     生成 PROJECT.md / docs/devlog.md / docs/specs/TEMPLATE.md / AGENTS.md / CLAUDE.md 五个文件
status   只报机械事实：project / branch / dirty / specs / last log / caps。不解析正文语义，不推断 focus 或 lifecycle。
spec     从模板创建文件
render   CLI 内置，单向生成 docs/project.html；不向用户项目下发 renderer 脚本
```

零原生依赖，`npm install` 不得触发 C++ 编译。`render` 只是 projection capability——它缺席不损害 continuity，Markdown 本身就可被人和 AI 直接阅读。详细行为与实现验收由 `docs/specs/3.1-minimal-cli.md` 拥有，本节只保留结果口径。

### 7. 迁移顺序（顺序本身是设计的一部分）

```text
1  annotated tag v2.4-governance-freeze（不用 -final，SemVer 里那是 prerelease 标识）
2  branch maintenance/2.x，今后只接 bug / security / compatibility
3  干净分支建 3.x skeleton，不复制 .evo-lite
4  只做 PROJECT.md + specs/ + devlog.md + renderer
5  dogfood：全新 agent 只读这三样，考它「项目是什么 / 在哪 / 下一步」
6  通过后才实现极小 CLI
7  fresh clone -> npm install -> init -> status -> render -> test 全绿，main 才切 3.x
```

先让 3.x 在干净分支上独立成立，再切 main，不存在「拆到一半发布链也断了」的窗口。当前 `package.json` 的 `test` / `test:governance` / `prepublishOnly` 仍指向 `.evo-lite/cli`，这个耦合必须在第 7 步整体替换，不能提前单点拆除。

### 8. 产品身份与发布通道

包名保留 `create-evo-lite`。顶层用户任务没变——给项目安装一套让人和 AI 能持续接手开发的基础设施；变的是实现哲学与产品边界，major version 足以表达这种断裂。另起包名会留下「两个包是什么关系」的长期解释负担。

npm dist-tag 三条通道：`latest` 指向 2.4.x，现有用户普通安装仍拿到稳定的 Governance Runtime；`next` 指向 3.0.0-beta.x，测试入口是 `npx create-evo-lite@next init`；`legacy` 长期保留最后一个 2.4.x。dogfood 与 fresh clone 全部通过后，才把 `latest` 切到 `3.0.0`。

## Acceptance Criteria

- [ ] `v2.4-governance-freeze` annotated tag 已打在 2.x HEAD
- [x] `maintenance/2.x` 分支已建立
- [x] 3.x 分支树内不存在 `.evo-lite/`、`templates/cli/`、`legacy/`
- [x] `docs/lessons-v2.md` 存在且含上述三条经验，3.x backlog 为空
- [ ] Minimal CLI delivery satisfies `docs/specs/3.1-minimal-cli.md`.
- [x] Dogfood：未读过本对话的新 agent 仅凭三个核心对象即能正确说出项目定位、当前焦点、下一步；说不出即本 spec 未通过
- [ ] 3.0 pre-release 发布到 `next`，`latest` 仍指向 2.4.x
- [x] 本 spec 自身 <= 120 行

## Open Questions

- `maintenance/2.x` 的维护窗口多长？现有 hive 子仓是否需要显式迁移通知？
- `render` 的 HTML 风格：内联单文件模板，还是可替换主题？首版建议内联。
- PROJECT.md 的 eviction 由人手动做，还是 `status` 检测超限后提示？首版建议只提示，不自动搬运。
