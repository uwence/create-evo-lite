# Minimal CLI

## Goal

交付 3.x 的第一个可安装形态。`npx create-evo-lite@next init` 之后，任何项目都拥有三个核心对象，并能用 `status` 看到机械事实、用 `render` 得到一张可读的进度页。

可验收判据：fresh clone → `npm install` → `init` → `status` → `render` → `test` 全绿，全程零原生编译。

## Non-goals

- 不做 CI / GitHub Actions。那是交付基础设施，够格单独一份 spec。
- 不做 search adapter、MCP、git hook、dashboard engine。禁区不变。
- 不提供 `--force`。3.1 不拥有覆盖用户文件的能力——那是不可逆操作。
- 不创建也不修改 `.gitignore`，不修改任何已存在文件。
- 不为 `PROJECT.md` 建 AST / IR，不推断 focus、lifecycle、blocked / doing / done。
- 不向用户项目下发 renderer 脚本。

## Design

### 1. 四个命令

```text
init     写五个文件：PROJECT.md / docs/devlog.md / docs/specs/TEMPLATE.md / AGENTS.md / CLAUDE.md
status   只报机械事实，见 §2
spec     从 docs/specs/TEMPLATE.md 复制出一份新 spec
render   CLI 内置，读 PROJECT.md + specs 文件信息 + 最近 devlog，单向生成 docs/project.html
```

`init` 只创建不存在的文件；任何已存在文件保持 byte-for-byte 不变；部分安装时补缺，并逐项打印 `created` / `skipped`——静默跳过会让人以为装全了。结束时提示用户把 `docs/project.html` 加进 `.gitignore`，但不代劳。

`render` 是 projection capability：它缺席只损失 HTML，不损失接手能力，因为 Markdown 本身就可被人和 AI 直接阅读。

### 2. status：数据源钉死

```text
Project    package.json 的 name，缺失时退回目录名
Branch     git
Dirty      git
Specs      docs/specs/*.md 的文件系统信息
Latest     同上，最新一个文件名
Last log   docs/devlog.md 的第一个二级标题
Caps       只计行数，见 §4
```

明确禁止：解析 `Now` 正文、推断 focus 或 state、判断 blocked / doing / done、解析 Milestones 语义、从 checkbox 推导 lifecycle、建立 `PROJECT.md` 的 AST 或 IR。

### 3. structure 与 semantics 的分界

```text
status 不得 import renderer 的 parser，也不得通过 shared semantic AST 间接依赖它。

render parser output may flow only to presentation.
It must not become input to status, lifecycle, focus, or state decisions.
```

第一句是 30 秒可检查的形状，第二句说明它保护什么。`status` 允许自己做极薄的逐行结构扫描。

### 4. caps：单一计数规则

八个段标题统一写成 `## Name (<= N)`，不带 lines / rows / items 字样。计数规则只有一条：

> 统计 section 内的非空源文本行。不计 section heading、代码围栏行本身、Markdown 表格的表头与分隔行。其余每个非空源文本行计 1。

不按 section 名称特判，因此不需要理解任何一句自然语言。超限只展示，不阻断：

```text
Caps    OVER — Decisions 21/20
exit    0
```

### 5. 预算

production JS 合计 <= 800 行，`test.js` <= 200 行。两者都是设计预算，不做自动 line gate——超出时不许压缩代码保行数，而应重审 scope。

模板是纯文本 **seed，不是 mirror**：`init` 之后用户的文件允许永久分叉，不存在任何同步合同。这正是它与 2.x `templates/cli` ↔ `.evo-lite/cli` 那种逐字节镜像的根本区别，因此不计入预算。

### 6. Windows

```text
ASSUMPTION  尚未在真实 Windows 上执行。
ACTION      只用 path.join / Node fs / execFile；禁止 shell、symlink 假设、路径大小写假设。
STATUS      Not blocked.
```

Assumed 管「能不能继续工作」，AC 管「有没有证据宣布完成」。两者不合并，也不互相代替。

## Acceptance Criteria

- [ ] fresh clone 后 `npm install` 成功，且未触发任何原生编译
- [ ] `init` 在空目录生成 §1 所列的五个文件
- [ ] `init` 对已存在文件保持 byte-for-byte 不变，并逐项打印 created / skipped
- [ ] `init` 不创建也不修改 `.gitignore`
- [ ] `status` 的输出只来自 §2 钉死的数据源，不读取任何段落正文
- [ ] `status` 在无 git、无索引、无 hook、无 MCP 的目录中成功
- [ ] caps 按 §4 的单一规则计数，八个段的实测值与人工核算一致
- [ ] caps 超限时 `status` 打印 `OVER` 并以 exit code 0 退出
- [ ] `render` 内置于 CLI；运行后用户项目中不存在 renderer 脚本
- [ ] `render` 生成 `docs/project.html`，且全部源文件在前后哈希一致
- [ ] `status` 的模块依赖图中不出现 renderer 的 parser
- [ ] production JS 合计 <= 800 行，`test.js` <= 200 行
- [ ] Windows smoke test：install / init / status / render 全部成功
- [ ] 本 spec 自身 <= 120 行

## Open Questions

- `spec <name>` 的文件名规则：直接用 slug，还是加日期前缀？3.0 用的是无日期。
- `status` 在没有 `PROJECT.md` 的目录里，应报错还是打印「未初始化」？倾向后者——报错会让它变成 gate。
- `render` 的 HTML 主题化仍未定，首版内联。
